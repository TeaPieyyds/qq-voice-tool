# QQ 语音发送助手

把**任意音频**变成 QQ 里能直接播放的语音消息——保留原录音的文件名，一步替换，点开就是你想要的音频。

有**电脑版**和**手机版**两个实现，功能一致，按你的使用场景选一个。

```
任意音频 → 24kHz 单声道 → SILK 编码 → 写入 QQ 的 ptt 缓存（文件名不变）
```

## 它解决什么问题

手写 QQ 语音的思路是"录一条 → 取消 → 找到那条录音的缓存文件 → 转成 SILK → 覆盖它 → 发送"。
这个流程本身能work，但实际操作要：

1. 在 QQ 里录一条再取消（只为拿一个能发送的"坑位"）
2. 打开 `Android/data/com.tencent.mobileqq/.../ptt/202610/19/` 找到刚生成的文件
3. 记住那串 `stream_2026101917415251.slk` 的文件名
4. 把音频转成 SILK（多数工具出来的是**手机端播不了**的格式，见下文）
5. 覆盖回去，名字不能错一个字符

本工具把 2~5 步全部自动化，你只需要：

```
录一条 → 取消 → 拖个音频进去 → 点「替换」→ 回 QQ 发送
```

## 两个版本怎么选

| | 电脑版 | 手机版 |
|---|---|---|
| 运行环境 | Windows + Node.js 18+ | Android 11+ |
| 依赖 | USB 数据线 + ADB | Shizuku（免 root） |
| 适合 | 坐在电脑前、批量折腾 | 随时随地、不想开电脑 |
| 使用门槛 | 低（插线即用） | 中（需装 Shizuku 并每次重启后激活一次） |
| 位置 | 本仓库根目录 | [`android/`](android/) |

两个版本读的是**同一个文件**，改完结果完全等价，可以混用。

## 快速开始 · 电脑版

**要求**：Windows 10/11、Node.js 18+、手机开 USB 调试。

1. 双击 `启动.bat`（首次会自动 `npm install`，浏览器会打开 `http://127.0.0.1:8791`）
2. 数据线连手机，手机上选「传输文件」并解锁
3. 首次使用按页面提示开 **USB 调试**：设置 → 关于手机 → 连点版本号 7 次 → 开发者选项 → USB 调试
4. 拖入音频，或直接粘贴文件路径回车
5. 列表自动选中**最新一条**录音 → 点「替换并保持文件名」
6. 回手机 QQ，点开那条语音试听、发送

> 用完关掉黑色命令行窗口即停止服务；窗口丢了就双击 `停止.bat`。

详细说明见 [`docs/电脑版.md`](docs/电脑版.md)。

## 快速开始 · 手机版

1. 安装 [`android/out/app-signed.apk`](android/out)（允许"安装未知来源应用"）
2. 安装 [Shizuku](https://github.com/RikkaApps/Shizuku/releases) 并启动它的服务：
   - **无线调试**（推荐）：连 Wi-Fi → 开发者选项 → 无线调试 → Shizuku 里「配对」输 6 位码 → 「启动」
   - **USB**：插线用电脑跑 `adb shell <shizuku lib 路径>`（Shizuku 界面里有现成命令）
3. 打开「QQ 语音助手」→ 点「授权」→ 手机上点「允许」
4. QQ 里录一条再取消 → App 里选音频 → 「替换并发送」

> **重要**：用 USB 启动的 Shizuku，**一拔数据线服务就被系统清掉**（至少在本项目测试的 vivo 机型上）。
> 想拔线用，必须走无线调试启动。无线调试启动后，即使关掉无线调试、关掉开发者选项，服务仍能保持运行。

详细说明见 [`docs/手机版.md`](docs/手机版.md)。

## 原理

### 1. QQ 语音的真实格式

手机 QQ 的 `.slk` 不是标准 SILK 文件，而是：

```
[0x02] + "#!SILK_V3" + ([uint16 帧长][20ms SILK 帧]) × N
```

- **`0x02` 这个前缀必须存在**。手机端解码器严格校验，缺了直接报错；PC 端宽容（会跳到 `#!SILK_V3` 继续解）——
  这就是网上那些工具"电脑能播、手机不能播"的根因
- 不需要 `FF FF` 结束符，帧链正常结束在 EOF 即可
- 采样率来自解码端约定（24kHz），码流里不存

所以本项目不是"改个后缀"，而是真的走了一遍
`解码 → 下混单声道 → 重采样 24kHz → SILK 编码 → 结构校验`，产物与 QQ 原生录音同构。

### 2. 为什么必须借 shell 权限

QQ 的语音在 `Android/data/com.tencent.mobileqq/...`，从 Android 11 起这块目录对其他应用是**硬封锁**的：

- 普通 App（含文件管理器）进不去
- 连「所有文件访问权限」（MANAGE_EXTERNAL_STORAGE）也明确不覆盖它
- 只有 **shell 身份**（uid 2000）能读写

所以：

- 电脑版走 **ADB**（adb shell 天然是 shell 身份）
- 手机版走 **Shizuku**（把 shell 身份借给 App，免 root）

顺带一提，**MTP（U 盘模式）只能读不能覆盖**——实测覆盖同名文件会静默失败，删文件也要交互确认。
所以电脑版的扫描用 MTP 兜底，写入一律走 ADB。

### 3. 定位逻辑

```
候选根目录：/sdcard/Android/data/com.tencent.mobileqq/Tencent/MobileQQ
        ／ /storage/emulated/0/... ／ /storage/emulated/999/...（分身）
        ／ com.tencent.mobileqqi（国际版）／ com.tencent.qqlite（极速版）

选账号：比较各账号"最新一条录音的修改时间"，取最近在用的那个
找文件：ptt/YYYYMM/DD/*.slk → ptt/YYYYMM/*.slk → ptt/*.slk（命中即停）
读取：stat -c '%n|%s|%Y'，不解析 ls -l 的列位
```

> 为什么不一路兜到 `ptt/` 根目录：根下还有一批 **32 位 MD5 命名的 `.slk`**（如 `52e9cf81….slk`），
> 那是 QQ 收/发后的缓存副本，不是待替换的录音，混进来会让列表翻倍。

## 注意事项（务必先看）

### 关于时长

- **气泡上的秒数只是显示值**，音频会完整播放：录 1 秒也能塞 30 秒，不需要为对齐时长去录长语音
- 唯一真实的限制是 **QQ 单条语音 60 秒上限**，超过可能被截断，工具会提示

### 关于 QQ 只能发"最新一条"

QQ 只允许发送**刚录的那一条**，所以流程永远是：

```
录一条 → 取消 → 选中最新那条 → 替换 → 发送
```

列表默认已经选中最新一条，不用挑。

### 关于 Shizuku（手机版）

- 手机**重启后** Shizuku 服务会停，需要重新激活一次（无线调试 → Shizuku 点「启动」）
- USB 方式启动的，**拔线即失效**（见上文）
- 「配对」只需一次，之后都是"打开开关 → 点启动"
- 授权是持久的，不用每次点「允许」

### 关于备份

每次替换前，原文件都会自动备份：

- 电脑版：`备份/<时间戳>/`
- 手机版：`Download/QQ语音备份/<时间戳>/`

出问题把备份拷回去即可。

### 关于替换后没生效

QQ 会缓存已解码的音频。替换后如果还是旧声音：**退出聊天窗口重进**，或杀掉 QQ 重开。

### 关于数据安全

- 全程**本地处理**，不上传任何音频、不上报任何数据
- 不含统计、不含联网请求（除了首次 `npm install` 和下载 ADB 组件）
- 电脑版只在 `127.0.0.1` 监听，不对外开放

### 微信？做不了

不是没试。实测结论：微信把语音存在**应用私有目录**（`/data/user/0/com.tencent.mm/...`），
连 `adb shell` 都 `Permission denied`，免 root 拿不到也写不了；而且微信不支持转发语音消息。
详见 [`docs/手机版.md`](docs/手机版.md) 里的实测记录。

**想在微信里发任意音频，务实的选择是虚拟声卡**（VB-CABLE 之类）：让微信"录"一遍播放的声音。

## 常见问题

**Q：列表是空的？**
QQ 里先录一条再取消，然后点「刷新」。手机版还要确认 Shizuku 是「正在运行」。

**Q：手机版说「Shizuku 未运行」？**
打开 Shizuku 点「启动」。点右上角状态徽章可以手动重查。

**Q：替换成功了但 QQ 还是播旧声音？**
退出聊天重进，或杀掉 QQ 重开。

**Q：电脑版提示 MTP 找不到目录？**
部分机型（Pixel、部分小米/OPPO）的 MTP 根本看不到 `Android/data`。开 USB 调试走 ADB 即可。

**Q：能不用数据线吗？**
电脑版不行（ADB 需要线或无线调试配对）。手机版可以，走 Shizuku 的无线调试模式。

**Q：会改坏我的语音吗？**
每次替换前自动备份原文件。替换逻辑是"写入后校验字节数一致"，不一致会报错而不是静默失败。

## 兼容性

已在 **iQOO Neo10 Pro+ / Android 16 / QQ 最新版** 上完整验证。

检索逻辑对以下情况做了适配：

| 场景 | 处理 |
|---|---|
| 应用分身 / 工作资料（user 999） | 已覆盖 |
| 多 QQ 账号 | 按最新录音选账号 |
| QQ 国际版 / 极速版 | 已加入候选包名 |
| 按天分目录 / 按月平铺 / 完全平铺 | 三层降级匹配 |
| 跨天（`202610/19` → `202610/20`） | 每次刷新重新定位 |
| 部分机型 MTP 不暴露 `Android/data` | 提示改用 ADB |

深度定制 ROM 改了路径的，手机版设置里可以**手动填 QQ 号和目录**，留空则回到自动查找。

## 自己构建

### 电脑版

```bash
npm install
node server.js          # 或双击 启动.bat
```

### 手机版

不依赖 Gradle，纯命令行打包（约 10 秒）：

```bash
# 1. 装 Android SDK：platforms;android-34 + build-tools;34.0.0
#    并确保 java 17 在 PATH 里

# 2. 拉 Shizuku 依赖（固定 13.1.5）
cd android && bash fetch-libs.sh

# 3. 打包
ANDROID_HOME=/path/to/Android/Sdk bash build.sh
# 产物：android/out/app-signed.apk

# 4. 安装
adb install -r out/app-signed.apk
```

首次构建会自签名（`android/debug.keystore`，不入库）。

```
│  ├─ src/                    Java 源码
│  ├─ stubs/                  编译期注解占位
│  └─ assets/www/             手机版界面（与电脑版同源，做了适配）
└─ docs/                      详细文档
```
