# 手机版使用说明

把任意音频变成 QQ 里能直接播放的语音消息，全程在手机上完成，不需要电脑。

---

## 一、它是怎么工作的

```
选音频 → 解码（Web Audio）→ 24kHz 单声道 → SILK 编码 → 写入 QQ 的 ptt 缓存
```

QQ 的语音目录受 Android 保护（`Android/data` 下的东西普通 App 一律进不去），
所以借 **Shizuku** 的 shell 身份来写——这也是 MT 管理器这类工具走的路。

- 界面：WebView 加载内置页面（和电脑版同一套代码，做了手机适配）
- 编码：silK-wasm 在 WebView 里跑，产物带 `0x02` 前缀、不带 `FF FF` 结尾，与 QQ 原生录音同构
- 写入：`cat > 目标文件`，写完用 `wc -c` 校验字节数
- 备份：改写前自动把原文件复制到 `Download/QQ语音备份/<时间戳>/`

---

## 二、首次使用

1. 安装 `app-signed.apk`（需要允许「安装未知来源应用」）
2. 手机装好 **Shizuku**（已预装并授权过的话可跳过）
3. Shizuku 服务启动方式二选一：
   - **无线调试**：连 Wi-Fi → 开发者选项 → 无线调试 → Shizuku 里「配对」输 6 位码 → 「启动」
   - **USB**：插数据线，电脑端工具点「启动手机上的 Shizuku」
4. 打开 QQ 语音助手 → 若提示未授权，点「授权」→ 手机上点「允许」

> ⚠️ **实测注意**：USB 方式启动的 Shizuku，**一拔数据线服务就被系统清掉**（本机 vivo ROM 的行为），
> 想拔线用就必须走无线调试。无线调试启动后，即使关掉无线调试、甚至关掉开发者选项，服务仍能保持运行。

---

## 三、日常使用

```
QQ 里按住语音键随便说一句 → 松手 → 取消（只为了拿一个"坑位"）
→ 打开 QQ 语音助手 → 选音频 → 点「替换并发送」
→ 回 QQ 点开那条语音，听、发
```

- 列表默认显示最新 5 条，点「展开全部 N 条」查看更多，默认已选中最新那条
- **气泡上的秒数只是显示值**，音频会完整播放，录 1 秒也能塞 30 秒
- 唯一真实的长度限制是 QQ 单条 60 秒，超过工具会提示
- 替换后如果 QQ 还放旧声音，退出聊天重进或杀掉 QQ 重开

---

## 四、手机重启后要做什么

Shizuku 服务会停（免 root 的固有代价），需要重新拉起：

| 方式 | 步骤 | 适合 |
|---|---|---|
| 无线调试 | 连 Wi-Fi → 开无线调试 → Shizuku 点「启动」 | 不想碰电脑 |
| USB | 插线 → 电脑端工具点「启动手机上的 Shizuku」→ 拔线 | 在电脑旁 |

配对只需做一次，之后都是「打开开关 → 点启动」。

## 五、微信为什么没做

不是没尝试，是权限层面的死路。实测证据：

| 检查 | 结果 |
|---|---|
| `/sdcard/Android/data/com.tencent.mm/MicroMsg/<hash>/voice2/` | **不存在** |
| 录一条微信语音（不发送）后全盘扫描 | 0 个新文件 |
| **发送**一条微信语音后再扫 | 仅 xlog 和一个头像图，无音频 |
| `/data/user/0/com.tencent.mm` | `Permission denied`（shell 也进不去） |

微信把语音锁在应用私有目录里，Shizuku 的 shell 身份进不去，只有 root 能碰。
另外微信还不支持转发语音消息、风控也更严，即便能改文件，落地价值也有限。

**想在微信里发任意音频，务实的选择是虚拟声卡**（VB-CABLE 之类）：让微信"录"一遍播放的声音，全平台 100% 可播，不存在解码兼容问题。

## 六、路径检索与兼容性

### 检索策略（电脑版与手机版一致）

1. **候选根目录**（按顺序试，命中即用）：

   ```
   /sdcard/Android/data/com.tencent.mobileqq/Tencent/MobileQQ
   /storage/emulated/0/Android/data/com.tencent.mobileqq/Tencent/MobileQQ
   /storage/emulated/999/Android/data/com.tencent.mobileqq/Tencent/MobileQQ   ← 应用分身/工作资料
   /sdcard/Android/data/com.tencent.mobileqqi/Tencent/MobileQQ               ← QQ 国际版
   /sdcard/Android/data/com.tencent.qqlite/Tencent/MobileQQ                  ← QQ 极速版
   ```

2. **选账号**：遍历所有纯数字目录，比较各自"最新一条 slk 的修改时间"，
   取**最近有录音的那个**——多账号登录时，"第一个"不一定是正在用的那个。

3. **找文件（按层降级，命中即停）**：

   ```
   ① ptt/YYYYMM/DD/*.slk   ← 标准：按天分目录
   ② ptt/YYYYMM/*.slk      ← 按月平铺
   ③ ptt/*.slk             ← 完全平铺的兜底
   ```

   为什么不一路兜到根目录：`ptt/` 根下还有一批 **32 位 MD5 命名的 `.slk`**
   （如 `52e9cf81a5c53f5bbb56220227bb5878.slk`），那是 QQ 发送/接收后的**缓存副本**，
   不是待替换的录音。实测本机有 25 个，混进来会让列表翻倍且误导。

4. **跨天**：每次刷新都重新定位目录（不缓存），QQ 按天新建 `202610/20` 时自动跟过去；
   万一新目录被清空，自动退回最近有文件的那天。

4. **取元数据**：用 `stat -c '%n|%s|%Y'`，不解析 `ls -l` 的列位——
   不同 ROM 的 `ls` 列数可能不同，解析列位容易错位。

5. **不限定文件名前缀**：只要 `.slk` 都算，避免 QQ 改命名规则后全部过滤掉。

### 已知的不兼容场景

| 场景 | 表现 | 处理 |
|---|---|---|
| 应用分身 / 工作资料 | 标准路径下没有 ptt | 已覆盖 emulated/999 |
| 多 QQ 账号 | 列出的是另一个号的语音 | 已改为按最新录音选账号 |
| QQ 国际版 / 极速版 | 包名不同 | 已加入候选 |
| 目录层级变化 | `*/*/*` 匹配不到 | 已加 `find` 兜底 |
| **部分机型 MTP 不暴露 `Android/data`**（Pixel、部分小米/OPPO） | 电脑版 MTP 模式扫不到 | **ROM 层面无解，必须用 ADB**；工具会提示 |
| Android 11+ 沙箱 | 普通 App 进不去 `Android/data` | 手机版靠 Shizuku，不受影响 |
| 企业定制/深度定制 ROM 改了路径 | 全部候选都不中 | 需手动反馈实际路径后加入候选 |

## 七、出问题怎么排查

- **状态显示「Shizuku 未运行」** → 服务没起来，打开 Shizuku 点「启动」；点右上角徽章可以手动重查
- **提示未授权** → 点「授权」，手机上点允许（授权是持久的，不用每次点）
- **列表空** → QQ 里先录一条再取消，然后点「刷新」
- **写入失败** → 一般是被 QQ 占用，杀掉 QQ 重试；原文件在「备份」目录里
- **音质发闷/发尖** → 源音频采样率过低会被重采样到 24k，属正常损失

## 八、构建

源码在 `android/`，不依赖 Gradle，`build.sh` 一把梭：

```bash
cd QQ语音工具/android
bash build.sh          # 约 10 秒，产物 out/app-signed.apk
adb install -r out/app-signed.apk
```

依赖（已放在 `libs/`）：`dev.rikka.shizuku:api/provider/aidl 13.1.5`，以及自写的
`androidx.annotation.RestrictTo` 编译期占位（`stubs/`）。
